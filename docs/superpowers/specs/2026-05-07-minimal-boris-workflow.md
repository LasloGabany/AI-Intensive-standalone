# Minimal Boris Cherny Workflow

**Дата:** 2026-04-27  
**Статус:** Approved  
**Контекст:** Full-stack разработка клубной платформы (FastAPI + JS + data pipelines)

---

## Проблема

- Рутинный код (CRUD эндпоинты, UI компоненты, миграции) занимает слишком много времени
- CI мониторинг и фиксы делаются вручную
- Параллельные сессии запускаются бессистемно

## Решение

Два автономных Claude loop-агента, работающих параллельно с основной сессией.

---

## Архитектура

```
Ты (технический директор)
        │
        ├── Основная сессия (ты)
        │   └── сложные задачи, архитектурные решения, ревью
        │
        ├── Loop 1: CI-монитор (каждые 15 мин)
        │   └── проверяет тесты → если падают, чинит → коммитит фикс
        │
        └── Loop 2: Task-агент (каждые 30 мин)
            └── читает TODO.md → берёт задачу → пишет код → создаёт PR
```

---

## Компоненты

### Loop 1: CI-монитор

**Расписание:** каждые 15 минут

```
1. git status + проверка последнего CI результата
2. Если всё зелёное → спит до следующего запуска
3. Если красное → читает лог ошибки → пишет минимальный фикс → коммитит
4. Если не может починить → добавляет в TODO.md: "⚠️ CI: нужна помощь"
```

### Loop 2: Task-агент

**Расписание:** каждые 30 минут

```
1. Читает TODO.md → берёт первую задачу [ ]
2. Открывает worktree под неё (изолированная ветка)
3. Пишет код, тесты, коммитит
4. Создаёт PR с описанием
5. Помечает задачу как [done] в TODO.md
```

---

## Формат TODO.md

```markdown
# Task Queue

- [ ] FastAPI эндпоинт GET /clubs/{id}/members
- [ ] Таблица участников в admin panel
- [done] KPI виджет для дашборда
- [blocked] Миграция users таблицы — нужно решить схему
```

| Статус | Значение |
|--------|----------|
| `[ ]` | Готова к работе |
| `[done]` | Завершена, PR создан |
| `[blocked]` | Нужно твоё решение |

---

## Data Flow

```
9:00  Ты добавил 5 задач в TODO.md (5 минут)
        │
9:30  Loop 2 взял задачу #1 → worktree → код → PR
        │
10:00 Ты ревьюишь первый PR
        │
10:15 Loop 1 увидел красный тест → починил → закоммитил
        │
10:30 Loop 2 взял задачу #2 → worktree → код → PR
        │
22:00 Ты закрыл ноутбук
        │
09:00 следующего дня: ревьюишь 3-4 готовых PR
```

---

## Error Handling

| Сценарий | Действие |
|----------|----------|
| Loop завис / ушёл не туда | `/loop stop` → `git log` → `git reset` если нужно → перезапуск |
| Агент не может решить задачу | Сам помечает `[blocked]` с причиной → берёт следующую |
| PR содержит плохой код | Не мержишь → комментируешь в PR → loop правит при следующем запуске |
| Loops конфликтуют | Каждый loop в своём worktree — конфликты только при merge, решаешь ты |

**Правило безопасности:** loops никогда не делают `git push --force` и не мержат сами. Только создают PR. Ты — единственный кто мержит в main.

## Пошаговый запуск (1 час)

### Шаг 1: Подготовка (5 мин)

Создай `TODO.md` в корне проекта с первыми задачами.

### Шаг 2: Запуск CI-монитора (10 мин)

Открой новую Claude Code сессию и введи:

```
/loop 15m Проверь CI статус проекта.
Если тесты падают — найди причину и почини минимальным фиксом.
Если не можешь починить — добавь в TODO.md строку:
"- [blocked] CI: <описание проблемы>"
Если всё зелёное — ничего не делай.
```

### Шаг 3: Запуск Task-агента (10 мин)

Открой ещё одну новую сессию и введи:

```
/loop 30m Прочитай TODO.md. Найди первую задачу со статусом [ ].
Создай worktree для неё. Реализуй задачу полностью с тестами.
Создай PR. Пометь задачу как [done] в TODO.md.
Если задача непонятна — пометь [blocked] с причиной, возьми следующую.
```

### Шаг 4: Основная сессия (весь день)

- Работаешь над сложными задачами
- Добавляешь задачи в `TODO.md` по мере появления
- Ревьюишь готовые PR
- Снимаешь `[blocked]` статусы

---

## Эволюция (когда освоишься)

| Этап | Добавить |
|------|----------|
| Неделя 1-2 | Запускаешь loops вручную каждое утро |
| Месяц 1 | Добавляешь ночное расписание: loops продолжают работу после 22:00 |
| Месяц 2 | Добавляешь Loop 3: feedback-кластеризация из GitHub Issues |
| Месяц 3 | 5-10 параллельных сессий, специализированные loops per домен |

---

## Ключевой сдвиг мышления

> Твоя работа перестаёт быть **"написать код"**  
> и становится **"поставить задачу достаточно чётко, чтобы агент сделал её без вопросов"**.  
> Качество `TODO.md` напрямую определяет качество PR.
